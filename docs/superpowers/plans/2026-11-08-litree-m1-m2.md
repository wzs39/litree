# LitTree M1+M2（骨架 + 学习体验）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 桌面应用能加载"计算机+数学"嵌套数据包、钻取浏览、按硬门控点亮知识点、动效与进度持久化全部可用。

**Architecture:** Electron 双进程（main 只做文件与对话框；renderer 纯 TS 渲染 SVG+Canvas）。图逻辑全部收敛在 `src/renderer/core/` 纯函数模块（vitest 覆盖），视图层只消费 store 与 core 的输出。elkjs 在 Worker 中分层布局。

**Tech Stack:** Electron + electron-vite + TypeScript(strict) + elkjs + vitest + Playwright(`_electron`)。无 UI 框架。

**Spec:** `docs/superpowers/specs/2026-11-08-litree-design.md`（本计划实现其 M1+M2；M3 编辑器、M4 打磨另出计划）

## Global Constraints

- `contextIsolation: true`、`nodeIntegration: false`；preload 经 `contextBridge` 只暴露：`pack:list/load/default`、`progress:load/save`
- renderer 无 UI 框架；TS `strict: true`；Node ≥ 20
- 布局用 elkjs；动效令牌 fast 120ms / base 200ms / slow 400ms / 级联间隔 80ms，入场缓动 `cubic-bezier(0.16, 1, 0.3, 1)`
- 背景 `#0B1220`；图标零 emoji，24×24 网格 2px 描边，`src/renderer/view/icons.ts` 单一来源
- XP：知识点 +2；进度写临时文件后原子替换；自动保存 debounce 500ms
- `@media (prefers-reduced-motion)` 下全部动效退化 ≤150ms 状态切换
- cs-math 对账数：单元 192 / hard 260 / soft 400 / 知识点 8,411（偏差须在转换报告中显式列出）
- UI 中文；边方向：`from` = 前置，`to` = 依赖方
- hard/soft 边只允许连接 `kind: 'unit'` 的节点

## Review Focus

1. **进度里的孤立 id**（pack 更新后残留）→ 统计面板标"孤立"，不崩溃、不静默丢弃。pin：Task 4 `orphanedLitIds` 测试。
2. **损坏或半写入的 JSON**（pack/progress）→ pack 返回校验错误列表、progress 返回 null，绝不白屏崩溃。pin：Task 2 与 Task 5 测试。
3. **`prefers-reduced-motion` 用户** → 所有动效退化为 ≤150ms 切换。pin：Task 9 步骤断言 tokens.css 含该 media 规则；人工走查。
4. **知识点 > 20 的大单元视图** → elk 布局在 Worker 执行、UI 不冻结。人工验收（Task 8 注明），无常驻测试。
5. **hard+soft 混合成环或自环** → 加载（schema 校验）与编辑（环检测）两处都拒绝并返回冲突路径。pin：Task 2 / Task 3 测试。

```ts
export interface GraphIndex {
  nodeById: Map<string, PackNode>;
  childrenOf(id: string): PackNode[];
  leavesOf(id: string): PackNode[];            // 全部叶子后代
  unitsOf(id: string): PackNode[];             // unit 后代（含自身若为 unit）
  hardPrereqsOf(unitId: string): PackNode[];
  softPrereqsOf(unitId: string): PackNode[];
  hardDependentsOf(unitId: string): PackNode[];
}
export function buildGraphIndex(pack: Pack): GraphIndex
export function unitAvailable(unitId: string, index: GraphIndex, litLeaves: Set<string>): boolean
  // unit 的全部 hard 前置 unit 均 lit（lit(unit)=其叶子全 lit）
export function leafAvailable(leafId: string, index: GraphIndex, litLeaves: Set<string>): boolean
export type NodeState = 'locked' | 'available' | 'learning' | 'lit';
export function aggregateState(id: string, index: GraphIndex, litLeaves: Set<string>, learning: Record<string, string>): NodeState
  // leaf: lit=在集合; available=所属 unit available; learning 可标记任意层（lit 优先于 learning）
  // unit: lit=叶子全亮; 其余按 hard 前置
  // branch: lit=叶子全亮; locked=存在未解锁后代; available=至少一个后代可点亮
export function detectCycle(edge: PackEdge, pack: Pack): string[] | null  // 返回环路径（首尾同 id），无环 null
export function minimalHardClosure(unitId: string, index: GraphIndex, litLeaves: Set<string>): string[]
  // 未点亮的传递 hard 前置闭包，按依赖深度排序（前置在前），含目标 unit 自身
export function isLit(id: string, index: GraphIndex, litLeaves: Set<string>): boolean
```

- [ ] **Step 1: 写失败测试**（统一 fixture，与本计划 dev-mini.json 同构：`b1`(D1){ `u1`(3叶,无前置); `u2`(2叶, hard←u1) }; `b2`(D2){ `u3`(1叶, hard←u2) }）

用例：`unitAvailable('u2')` 空 lit=false、u1 全部叶子 lit=true；`leafAvailable` 随所属单元；`aggregateState`：u2 空 lit='locked'、u1 全亮后='lit' 且 u2='available' 且 b1='available'（u2 未全亮）、u2 叶子全亮后 b1='lit'；learning 标记 u1（未全亮）时='learning'；`detectCycle({from:'u2',to:'u1',type:'hard'})` 返回非 null 且首尾均为 'u1'；`minimalHardClosure('u3')` 空 lit = `['u1','u2']`、u1 全亮后 = `['u2']`；`isLit('b1')` 语义同聚合。
