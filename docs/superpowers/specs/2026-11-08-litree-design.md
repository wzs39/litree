# LitTree（点亮之树）设计规格

日期：2026-11-08
状态：待用户审阅

## 1. 背景与目标

学习一门学科的过程与论文引用网络类似：概念之间存在前置依赖，学会上游才能理解下游。本项目把一门学科建模为**带前置依赖的分层科技树**，学习者在其中**点亮节点**记录掌握进度，兼有游戏科技树的解锁感与学术引用链的可溯源性（每条前置边可附证据）。

### 1.1 现有项目调研结论

| 项目 | 结论 |
|---|---|
| zeroa234/cs-math-skill-tree（MIT） | 与本构想最接近：192 学习单元、260 条必须前置 + 400 条推荐前置、每条边附课程证据、防环检测、纯静态。短板：内容写死为 CS+数学、非通用工具、无嵌套钻取、无引用数据接入 |
| BOB0731/learning-tech-tree（MIT） | 通用 `learning-tech-tree/v1` schema、硬前置 AND 门控；缺资源/证据模型 |
| kamranahmedse/developer-roadmap（371k★） | 渲染器成熟但内容为分组话题列表、无硬前置 DAG、平台重、license 受限 |
| 引用图谱工具（Local Citation Network 等） | 只有论文引用网络可视化，无学习进度概念 |

**结论**：不存在同时满足"嵌套钻取 + 硬门控点亮 + 全功能编辑 + 桌面动态体验"的项目，自研桌面应用，数据层复用 cs-math-skill-tree 的带证据数据（MIT）。

### 1.2 成功标准

1. 打开应用即呈现"计算机 + 数学"学科树，可逐层钻取到知识点
2. 点亮一个单元时硬门控生效（前置未齐则锁定），动效符合第 9 节编排规范
3. 全功能可视化编辑：增删节点/连线、属性编辑、环校验、导入导出数据包
4. 进度本地持久化、可导出备份；重启后状态不丢
5. 图标零 emoji、全手绘 SVG；动效遵守统一 motion spec

## 2. 技术选型

| 决策 | 选择 | 依据 |
|---|---|---|
| 产品形态 | **纯静态 Web 应用**（2026-11-08 用户指示，由 Electron 迁移） | 动效/编辑器属 web 强项；零安装、可离线（打包后单目录静态托管）；pack fetch + localStorage 即满足全部需求 |
| 渲染栈 | 纯 TypeScript + SVG + Canvas（无 UI 框架） | 图渲染是核心复杂度；DOM 框架无增益 |
| 布局引擎 | **elkjs**（Worker 内运行） | 分层 DAG 布局成熟，cs-math-skill-tree 同款 |
| 构建 | Vite | 静态构建 + dev server |
| 测试 | vitest（单测）+ Playwright（Web e2e 冒烟） | |
| 运行环境 | Node ≥ 20（本机 v24.18，仅开发/构建用） | |

**非目标（本期不做）**：账号/云同步（localStorage 导出导入替代）、移动端适配、从文献 API（OpenAlex 等）自动生成引用边（列为未来扩展）、多人协作。

## 3. 总体架构

```
┌──────────────────────────────────────────────────────┐
│ 静态 Web 应用（Vite 构建，可离线托管）                  │
│                                                      │
│  ┌─ Renderer（TS + SVG + Canvas）────────┐            │
│  │ GraphCanvas   图谱渲染/动效/编辑画布   │            │
│  │ Sidebar       领域筛选/搜索/统计面板  │            │
│  │ DetailPanel   节点详情/属性编辑表单   │            │
│  │ Inspector     前置检查/点亮路径规划   │            │
│  └──────────────────────────────────────┘            │
│        │ fetch（数据包）  localStorage（进度）        │
└──────────────────────────────────────────────────────┘
```

- **宿主能力边界**：数据包经 `fetch('/packs/index.json' + '/packs/<file>.json')` 加载；进度经 `localStorage`（键 `litree:progress:<packId>`）；无其他宿主 API
- **文件布局**：
  - 数据包（静态资源，随构建发布）：`resources/packs/*.json` + `index.json` 清单（构建时复制到站点 `/packs/`）
  - 进度：浏览器 `localStorage`，按 packId 隔离；提供导出/导入 JSON 备份

## 4. 数据模型

### 4.1 数据包 `litree/pack-v1`

```jsonc
{
  "schema": "litree/pack-v1",
  "id": "cs-math",                       // 稳定 id，进度按它隔离
  "title": { "zh": "计算机 + 数学", "en": "CS & Math" },
  "domains": [ { "id": "A", "name": "离散结构", "color": "#3DD6C3" } ],
  "nodes": [{
    "id": "A.1.1",                        // 全局唯一，可读
    "parent": "math.analysis | null",     // 显式父指针，构成森林
    "kind": "branch | unit | leaf",       // 容器或叶子
    "title": { "zh": "证明基础", "en": "Proofs" },
    "domain": "A",                        // 领域 token（着色/筛选）
    "core": true,                         // 主干 / 选修（unit 层有意义）
    "summary": "…",
    "resources": [{ "title": "MIT 6.042", "url": "…", "lang": "zh|en" }],
    "exercises": ["…"],
    "evidence": "课程先修原文引用 + 链接",
    "layoutOverride": { "x": 0, "y": 0 }  // 用户手动拖动产生的偏移（可省）
  }],
  "edges": [{
    "from": "A.1.1", "to": "A.2.1",
    "type": "hard | soft",                // 必须前置（AND 门控）/ 推荐前置
    "reason": "为什么存在这条依赖"
  }]
}
```

**层级约定**（学科 → 分支 → 单元 → 知识点）：

- `L1` 学科（branch）：数学、计算机（由转换脚本按领域归类派生，映射表人工核对后固化）
- `L2` 分支（branch）：分析学、代数、离散结构……（对应 pack 的 domain 或其细分）
- `L3` 单元（unit）：192 个学习单元，硬前置边发生在这一层
- `L4` 知识点（leaf）：约 8,411 个，来自 cs-math 知识导览的章/节/知识点；**仅当单元内知识点 > 20 时保留章/节为中间分组层，否则单元下直接挂知识点**（避免无意义深层级）

**校验规则**（加载与编辑共用同一图核心模块）：
- 节点 id 全局唯一；`parent` 必须存在或为 null；森林无环（parent 链）
- 边端点必须存在；全图（含 kind 为 unit/leaf 的全部节点）加入 hard 边前做环检测（Kahn 拓扑），成环即拒绝并返回冲突路径用于高亮
- `domain` 必须在 `domains` 中声明

### 4.2 进度文件

```jsonc
{
  "packId": "cs-math",
  "lit":   { "A.1.1.k07": { "at": "2026-11-08T10:00:00Z", "note": "" } },
  "learning": { "math.analysis": "2026-11-08" },       // 任意层级可标记"学习中"
  "xp": 120,
  "history": [{ "id": "…", "at": "…", "xp": 10 }]      // 点亮时间线
}
```

- **点亮判定在叶子层**：知识点是唯一可手动点亮的节点；容器节点（单元/分支）状态由后代聚合（见 5.2），不可手动点亮
- XP：知识点 +2（统一）；容器不单独计分。主干/选修（core）仅作视觉与筛选标记
- "批量点亮本单元全部知识点"（上下文菜单，需该单元硬前置已满足）支持整课快速通关，逐个计分

## 5. 渲染与交互

### 5.1 画布与布局

- elkjs 分层布局：依赖深度分层、同层交叉最小化；`layoutOverride` 叠加用户手动位置
- 每个视图 = 一个容器节点的子图独立布局（单视图 ≤ ~200 节点）
- 滚轮平滑缩放（插值动画）、拖拽平移、minimap、领域筛选、搜索定位

### 5.2 节点状态机

| 状态 | 判定 | 视觉 |
|---|---|---|
| locked | unit：任一硬前置未点亮；branch：存在未解锁后代 | 暗色 + 锁图标；hover 列出缺失前置 |
| available | unit：硬前置全部点亮；branch：至少一个后代可点亮 | 微弱待机光晕 |
| learning | 用户手动标记（任意层级） | 琥珀描边脉冲 |
| lit | leaf：已手动点亮；unit/branch：全部叶子后代点亮（自动聚合，不可手动） | 全亮 + 呼吸动画；容器另显进度环（n/m） |

### 5.3 边

- 实线 = hard，虚线 = soft；箭头指向前置（从依赖指向被依赖）
- hover 节点 → 当前视图内上游依赖链高亮；缺失前置段红色强调；跨视图边显示为 stub 徽章（`← 来自外部：算法.图论`），点击跳转

### 5.4 钻取导航

- 双击容器 → 进入其子图视图；顶部面包屑 `计算机+数学 / 数学 / 分析学`；`ESC` / 返回键逐层退出
- 根视图 = L1 学科两大分支节点（各带总进度环）

### 5.5 点亮路径规划（Inspector）

- 选中任意未点亮节点（叶子自动映射到其所属单元）→ 计算并高亮其**最小必须前置闭包**（含跨视图计数），显示"还差 N 步"，逐项列出未点亮前置

## 6. 编辑器

- 编辑模式开关（工具栏 / `E` 键）
- 新建节点：双击画布空白 → 表单（kind/标题/父节点/领域/主干/摘要）；默认 kind=leaf，parent=当前视图容器
- 连线：从节点边缘拖拽到目标 → 边表单（hard/soft + 理由）→ 即时校验（端点存在 + 环检测）
- 属性面板：编辑全部字段；删除节点须确认（级联删除其子孙节点与关联边，确认文案注明数量）
- 编辑写入用户区 pack 副本（500ms debounce 自动保存）；一键"重置为原始数据包"
- hard 边只允许连接 unit 层节点（与门控层一致）；soft 边同理（保持证据语义）

## 7. 持久化

- 进度存 `localStorage`（键 `litree:progress:<packId>`），500ms debounce 自动保存；浏览器存储随站点隔离
- 进度导出/导入为独立 JSON 备份（含 schema 与 packId，导入时校验 packId 匹配）
- 数据包导出：编辑产生的用户副本导出为 pack JSON，可分享导入（M3 编辑器）

## 8. 内容管线（cs-math 迁移）

1. `git clone` https://github.com/zeroa234/cs-math-skill-tree（MIT，只读素材，clone 到仓库外的临时目录）
2. 转换脚本 `scripts/convert-csmath.ts`：
   - 读 `output/skilltree.json` → L2 分支 / L3 单元 / hard+soft 边 / 资源 / 练习 / 证据
   - 读 `output/outlines.json` → L4 知识点（含 >20 知识点的单元保留章/节分组层）
   - 领域 → 学科（L1）映射表内嵌于脚本，转换时人工核对后固化
3. 产物写入 `resources/packs/cs-math.json`
4. 对账断言：单元 192、hard 260、soft 400、知识点 8,411（±章节分组合并产生的差异需在脚本中显式报告）
5. 产物与 `index.json` 清单一同发布到站点 `/packs/` 路径

## 9. 视觉语言与动效编排

### 9.1 图标（自制 SVG，零 emoji）

- 24×24 网格、2px 描边、圆角端点、几何构造；约 40 枚 = 10 个领域字形 + 状态图标（锁/学习中/点亮/完成）+ UI 图标（搜索/缩放/筛选/编辑/导入导出/返回）
- 领域字形用学科符号在网格上重绘：∑（代数）、∫（分析）、π（几何）、∂（微分方程）、λ（函数式）、树形（离散）、◎（概率）等
- `icons.ts` 单一来源导出 SVG 字符串，`currentColor` 着色

### 9.2 主题

- 背景：近黑墨蓝 `#0B1220` + 细星点纹理；点亮节点是唯一强光源
- 领域色板手工挑选（数学 = 靛青系、计算机 = 琥珀系、离散 = 玉青……），每领域固定 token
- 中文界面用系统黑体栈；节点 ID/公式用等宽字体；标题字重 ≤ 600

### 9.3 Motion Spec

**令牌**：fast 120ms / base 200ms / slow 400ms / 级联间隔 80ms；入场缓动 `cubic-bezier(0.16, 1, 0.3, 1)`。

**点亮仪式五拍**：
1. 0ms 按下：内缩 2% + 描边加亮
2. 120ms 绽放：径向光晕扩张至 1.4× 回落
3. 200ms 粒子：8–12 枚光尘沿出边飘向下游（Canvas 层，全屏上限 200 枚）
4. 280ms XP 数字滚动 + 飘字
5. 360ms+ 下游新解锁节点按深度错峰亮起（每层 +80ms），锁图标淡出

**规则**：
- 已点亮节点 3s 周期呼吸（光晕 ±4%）
- 误触锁定节点：轻微抖动 + 锁图标确认动画
- 动画只用 transform/opacity；呼吸/光晕走 CSS，粒子走独立 Canvas 层
- 尊重 `prefers-reduced-motion`：全部退化为 ≤150ms 状态切换
- 图标点亮三帧小序列：锁 → 开锁 → 勾（150ms）

## 10. 测试策略

- **单测（vitest）**：图核心纯函数——门控判定（unit 的叶子可点亮 ⇔ 该 unit 全部 hard 前置 unit 已 lit）、环检测、最小前置闭包、容器聚合状态、schema 校验、XP 计算、进度迁移
- **e2e 冒烟（Playwright，Web）**：启动 dev/preview 站点 → pack 加载（对账数量）→ 点亮一个无前置知识点 → 重载页面验证 localStorage 状态保持
- 动效观感与编辑流程：人工验收清单

## 11. 实施里程碑

| 阶段 | 交付 |
|---|---|
| M1 骨架 | Electron 工程 + IPC 白名单 + pack 加载/校验 + elk 布局静态渲染 + 嵌套钻取 |
| M2 学习体验 | 状态机 + 硬门控点亮 + 五拍动效 + 进度持久化 + 统计面板 + 点亮路径规划 |
| M3 编辑器 | 增删节点/连线 + 环校验 + 属性面板 + 导入导出 + 重置 |
| M4 打磨 | minimap、搜索、领域筛选、设置、视觉细节走查 |

## 12. 边界情况

- **大 pack 性能**：单视图节点数上限约 200（嵌套保证）；布局计算放 Web Worker，避免阻塞主线程
- **进度与 pack 漂移**：进度里引用的 id 在 pack 中不存在时保留数据但在 UI 标记"孤立进度"，可一键清理
- **导入第三方 pack**：schema 校验失败时逐条列出错误，不部分加载
- **环检测反馈**：成环时高亮冲突路径上的节点并给出环序列文本
- **知识点极多的单元**（>20）：章/节分组层兜底；单组仍 >50 时 elk 分层 + 视图内折叠

## 13. 风险

| 风险 | 缓解 |
|---|---|
| cs-math 数据格式与 README 描述不符 | 转换脚本先做结构探测，字段映射失败即报错而非猜测（已执行，见转换报告） |
| 知识点数量对账有出入（PDF 抽字差异等） | 脚本显式输出差异报告，人工确认后固化（leaves=8,124，见实施账本） |
| elkjs 对 >200 节点布局慢 | 嵌套钻取天然限制单视图规模；Worker 隔离 |
| localStorage 容量/清除 | 进度体积远小于 5MB 配额；提供导出备份；站点数据被清除时提示导入恢复 |
| 静态托管的 CORS/路径 | 同源 fetch（/packs/ 相对路径），本地 file:// 以 `npx serve dist` 或任意静态服务器托管 |
